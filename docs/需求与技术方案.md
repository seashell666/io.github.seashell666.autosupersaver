# 小米自动超级省电 · 需求与技术方案（v0.1）

- 编写日期：2026-11-07
- 目标设备：小米 11（Android 13 / MIUI 14），已 root
- 技术底座：Vector（libxposed API 102）Xposed 模块，Kotlin
- 状态：需求草案，待确认 4 个前提后进入开发

---

## 1. 一句话目标

手机电量低于可配置阈值（默认 17%）且**未在充电**时，自动让系统进入「超级省电模式」；恢复充电或电量回升后自动退出。

## 2. 为什么用 Xposed 模块，而不是普通 App

| 方案 | 可行性 | 问题 |
|---|---|---|
| A. Vector 模块（本方案） | 高 | 需 root + Zygisk + Vector；但逻辑跑在系统进程里，不受 MIUI 后台管控 |
| B. 普通 App + root shell | 中 | 需常驻后台，MIUI 会杀；每次都要 su 弹窗 |
| C. Shizuku + 普通 App | 中 | 重启后需重新授权，超级省电会禁用大部分后台 |
| D. 无障碍模拟点击 | 低 | 界面改版即失效，误触风险高 |

结论：A 是唯一能"设完就不用管"的形态。代价是设备必须已 root 并装好 Vector。

## 3. 前提条件（阻塞项，需确认）

1. 手机已解锁 BL 并 root（Magisk / KernelSU），Zygisk 已开启。
2. 已刷入 Vector 2.x，管理器显示框架激活、API 102。
3. 手机可直接用数据线连电脑 adb 调试（决定迭代速度）。
4. 构建环境可用：JDK 17+、Android SDK（platform 34/35、build-tools）、Gradle 8.x。

> 备注：本机（C:/D:/F: 常规路径）只找到 adb platform-tools，未发现 JDK 与 Android SDK，需要确认构建环境在哪台机器/哪个虚拟机。

## 4. 功能需求

### P0（MVP 必须有）

| 编号 | 需求 | 说明 |
|---|---|---|
| FR-1 | 电量监听 | 系统级电池回调，1% 粒度；不轮询、不常驻定时器，几乎零额外耗电 |
| FR-2 | 阈值可配置 | 默认 17%，范围 5–50%，步进 1%；改完立即生效，不需重启 |
| FR-3 | 充电状态判定 | 仅"未充电"时触发；充电中/充满/无线充/反向充电都不算 |
| FR-4 | 触发动作 | 进入系统「超级省电模式」，行为与手动点开关一致 |
| FR-5 | 退出条件 | ① 插入充电 ② 电量 ≥ 阈值+5（默认 22%）③ 手动关闭；三条任一满足即退出 |
| FR-6 | 去重与防抖 | 同一放电周期只触发一次；触发后 30 分钟冷却；拔插充电器抖动不重复触发 |
| FR-7 | 总开关 | 模块内一键启用/停用，停用后系统行为完全恢复原状 |
| FR-8 | 状态可见 | 触发时发一条通知（可关）；设置页显示当前电量/充电状态/上次触发时间 |

### P1（稳定版加）

| 编号 | 需求 | 说明 |
|---|---|---|
| FR-9 | 触发日志 | 本地环形日志（最近 100 条），便于排查为什么没触发/误触发 |
| FR-10 | 阈值滞回可调 | 退出回差默认 +5%，可改（3–10%） |
| FR-11 | 生效时段 | 如 23:00–07:00 不触发（避免半夜切桌面） |
| FR-12 | 白名单提示 | 说明超级省电下哪些 App 会不可用，允许跳转系统白名单设置 |

### P2（可选）

- FR-13 快捷开关磁贴：手动一键进出超级省电。
- FR-14 触发前 30 秒倒计时通知，可"取消本次"。
- FR-15 充电到 100% 时清空本周期触发标记。

### 明确不做

- 不做通用省电调度/降频，不改系统分区文件，不替换系统 App。
- 不做多机型/多 ROM 适配（先只保证 Mi 11 + Android 13）。
- 不上传任何数据，不联网。

## 5. 非功能需求

| 类别 | 要求 |
|---|---|
| 稳定性 | Hook 全部 try/catch + `ExceptionMode.PROTECTIVE`；任何异常不得抛进 BatteryService/PowerManagerService，禁止造成 system_server 崩溃或开机卡死 |
| 可回滚 | 卸载 APK 即恢复；提供"安全模式"说明（如何用 Magisk 禁用模块救砖） |
| 性能 | 空闲时零唤醒；电量变化回调内只做几次整型比较；单次触发耗时 < 100ms |
| 兼容 | Android 13 / MIUI 14；对 HyperOS 做能力探测，找不到入口时降级为"普通省电模式"并提示 |
| 权限 | 模块侧不需要额外运行时权限；设置页仅在改阈值时写本地配置 |

## 6. 技术方案

### 6.1 模块形态

单个 APK 承担两个角色：

- **普通 App 部分**：Compose 设置页（阈值、开关、回差、日志）。
- **Xposed 入口**：`XposedModule` 子类，`META-INF/xposed/java_init.list` 声明；`module.prop` 里 `minApiVersion=102`、`targetApiVersion=102`、`staticScope=true`，`scope.list` 至少包含虚拟包名 `system`，并按勘察结果加 `com.miui.powerkeeper`。

依赖：`compileOnly("io.github.libxposed:api:102.0.0")`、`implementation("io.github.libxposed:service:102.0.0")`。
API 102 的好处：只有一个 Java 入口类时可热重载——改 Hook 逻辑不用重启系统进程，这对 system_server 侧的调试是决定性的。

### 6.2 三条触发路径（按优先级）

| 路径 | 做法 | 优点 | 风险 |
|---|---|---|---|
| A（首选） | 注入 `com.miui.powerkeeper`，反射调用系统设置页开关所走的同一个内部方法（如 `PowerSaveController#setSuperPowerSave(true)` 一类） | 与手动操作完全等价，含桌面切换等副作用 | 需要反编译确认类名/方法名，随 ROM 更新可能变 |
| B | 注入 `system_server`，通过 Binder 拿 powerkeeper 服务或发 MIUI 内部广播 | 权限最高，可做兜底 | 服务接口不公开，需 `service list` 勘察 |
| C（兜底） | 直接拉起超级省电 Activity / 模拟点击 | 一定"能点" | 会闪界面、需确认弹窗，体验差，不作为交付形态 |

先做 1 小时可行性验证：手动开一次超级省电，抓 `logcat` 与 `dumpsys`，确认路径 A 或 B 是否存在。**这一步决定后面是 3 天还是 8 天。**

### 6.3 电量与充电判定

- 在注入进程内注册 `ACTION_BATTERY_CHANGED`（sticky，立刻拿到当前值），或 hook `BatteryService` 的电量处理函数。
- 充电判定：`status ∈ {CHARGING, FULL}` 或 `plugged != 0`；同时排除无线充（`BATTERY_PLUGGED_WIRELESS`）按需处理。
- 触发判定顺序：总开关 → 冷却窗口 → 充电状态 → 电量阈值 → 本次放电周期是否已触发 → 执行。

### 6.4 配置读取

设置页与模块不同进程。方案：模块内实现一个 `ContentProvider`，用签名级自定义权限保护，system 侧以 uid 1000 读取；设置页写入。避免直接读 `/data/data/.../shared_prefs`（SELinux 会拦），也不依赖已移除的 legacy `XSharedPreferences`。

### 6.5 关键防御

- 全局失败计数：连续 3 次调用失败即自动停用并写日志，防止在异常 ROM 上反复尝试拖慢系统。
- 状态持久化：`lastTriggerCycle`、`lastTriggerTime` 存本地，重启后不重复触发。
- 版本探测：`Build.VERSION.INCREMENTAL` / MIUI 版本号变化时，清空反射缓存重新解析。

## 7. 验收用例

| # | 场景 | 期望 |
|---|---|---|
| 1 | 未充电，电量 18% → 17% | 不触发（阈值是"≤"时按配置，默认 17 触发，需明确边界） |
| 2 | 未充电，电量降到 16% | 进入超级省电，发一次通知 |
| 3 | 17% 正在充电，拔线 | 拔线后下一次电量变化即触发 |
| 4 | 超级省电中插入充电器 | 自动退出，桌面恢复 |
| 5 | 触发后重启手机 | 不重复触发（同一放电周期） |
| 6 | 设置页把阈值改 25% | 立即生效，无需重启 |
| 7 | 5 秒内反复拔插充电器 10 次 | 只触发 1 次，无抖动 |
| 8 | 停用模块 | 一切行为恢复原生，无残留通知 |
| 9 | 连跑 72 小时 | 无 system_server 异常重启，待机耗电增量 < 1%/天 |
| 10 | 卸载 APK 后重启 | 系统正常启动，无 bootloop |

## 8. 风险

| 编号 | 风险 | 概率 | 影响 | 应对 |
|---|---|---|---|---|
| R1 | powerkeeper 无稳定内部入口，只能走 UI 模拟 | 中 | 工期 +3~4 天，体验下降 | 先做勘察；不行则降级为"普通省电模式 + 提示" |
| R2 | 超级省电会切极简桌面，自动触发很打扰 | 高 | 体验问题 | 加生效时段、倒计时取消、触发前提示 |
| R3 | 系统把"超级省电"与充放电状态机强耦合（插电自动退出） | 中 | 需求冲突 | 按 ROM 实测，必要时改为"自行关闭被限制的应用"替代方案 |
| R4 | 反射方法随 MIUI/HyperOS 版本变动 | 中 | 升级后失效 | 多签名匹配 + 版本探测 + 失败自动停用 |
| R5 | 未 root 或 Vector 未激活 | — | 方案不成立 | 开工前确认 |
